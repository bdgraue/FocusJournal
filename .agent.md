## 🎯 Common Tasks & How to Do Them

### Adding a New Feature
1. Check existing patterns in similar screens
2. Use Material 3 widgets (`FilledButton`, `OutlinedButton`, etc.)
3. Add localization keys in `lib/l10n/translations/`
4. Update tests if touching BackupService or core logic
5. Run `flutter analyze && flutter test`

### Fixing a Bug
1. Reproduce the bug (check test files for examples)
2. Write a failing test first (TDD approach)
3. Fix the bug
4. Ensure test passes
5. Check for regressions: `flutter test`

### Updating Dependencies
1. Check breaking changes in changelog
2. Update `pubspec.yaml`
3. Run `flutter pub get`
4. Fix any API changes (see examples in git history)
5. Test thoroughly: widget tests + manual testing
6. Update CLAUDE.md if significant changes

### Adding Tests
- **Widget tests**: Use `test/widget_test.dart` as template
- **Service tests**: See `test/services/backup_service_test.dart`
- **Avoid timeouts**: Don't use `pumpAndSettle()` with async operations
- **Mock carefully**: Auth screens need SharedPreferences + SecureStorage mocks

## 📝 Code Patterns You Should Follow

### 1. BuildContext After Async
```dart
// CORRECT
if (!mounted) return;
ScaffoldMessenger.of(context).showSnackBar(...);

// WRONG - can cause errors
await someAsyncOperation();
ScaffoldMessenger.of(context).showSnackBar(...);  // Missing mounted check!
```

### 2. Lock Suppression Pattern
```dart
// ALWAYS use try-finally
final lockSuppression = context.read<LockSuppression>();
try {
  lockSuppression.value = true;
  await fileOperation();
} finally {
  lockSuppression.value = false;  // CRITICAL
}
```

### 3. Password Security
```dart
// Clear password after successful operation
_passwordController.clear();
setState(() => _isPasswordVisible = false);

// Clear password on app backgrounding
@override
void didChangeAppLifecycleState(AppLifecycleState state) {
  if (state == AppLifecycleState.inactive || state == AppLifecycleState.paused) {
    _passwordController.clear();
  }
}
```

### 4. RadioGroup (NOT RadioListTile)
```dart
// CORRECT (Flutter 3.32+)
RadioGroup<ThemeMode>(
  groupValue: themeMode,
  onChanged: (value) => _updateTheme(value!),
  child: Column(
    children: [
      ListTile(
        title: Text('Option 1'),
        leading: Radio<ThemeMode>(value: ThemeMode.system),
        onTap: () => _updateTheme(ThemeMode.system),
      ),
    ],
  ),
)

// WRONG (Deprecated)
RadioListTile<ThemeMode>(
  value: ThemeMode.system,
  groupValue: themeMode,  // Deprecated!
  onChanged: (value) => _updateTheme(value!),  // Deprecated!
)
```

## 🧪 Testing Guidelines

### Expected Test Format
```dart
group('ComponentName', () {
  late ServiceOrWidget component;

  setUp(() {
    component = ServiceOrWidget();
  });

  group('Feature Set', () {
    test('specific behavior description', () {
      // Arrange
      final input = {...};

      // Act
      final result = component.method(input);

      // Assert

    });
  });
```

## 🚫 Anti-Patterns to Avoid

### Don't
- ❌ Use deprecated APIs (RadioListTile, old local_auth, etc.)
- ❌ Add dependencies without checking for breaking changes
- ❌ Skip `flutter analyze` before committing
- ❌ Use `pumpAndSettle()` in widget tests (causes timeouts)
- ❌ Log sensitive data (passwords, keys, tokens)
- ❌ Forget to clear passwords after operations
- ❌ Use BuildContext after async without `mounted` check

### Do
- ✅ Follow Material 3 design patterns
- ✅ Add comprehensive tests for new features
- ✅ Document security-critical code inline
- ✅ Use proper error handling (try-catch-finally)
- ✅ Clear sensitive data from memory
- ✅ Check `mounted` before using BuildContext
